Features

Everything you need for
modern communication

AfterLink replaces HTTP, WebSockets, and gRPC with a single, unified protocol that's faster and easier to use.

Binary Protocol

10-byte frame header with MessagePack serialization. 90% smaller than HTTP headers.

Request/Response

RPC-style calls with automatic correlation via message IDs. Multiplex hundreds of requests over one connection.

Pub/Sub Built-in

Real-time topic-based publish/subscribe. No separate WebSocket server needed.

Schema Validation

Automatic payload validation with Zod. Invalid payloads rejected before your code runs.

Auto-Reconnect

Exponential backoff with jitter for connection resilience. Clients recover from network drops automatically.

Backend Agnostic

Works with Supabase, InsForge, Firebase, AWS, MongoDB, PostgreSQL, or any custom backend.

Quick Start

Hello World in 5 minutes

Build your first AfterLink server and client.

1

Create the Server

server.js 
const { Server } = require('@afterlink/server');

const server = new Server({ port: 4000 });

server.on('ping', async (req, res) => {
  res.send({ message: 'pong', timestamp: Date.now() });
});

server.listen();
console.log('Server running on port 4000');
2

Create the Client

client.js 
const { Client } = require('@afterlink/client');

async function main() {
  const client = new Client('afterlink://localhost:4000');
  await client.connect();

  const result = await client.request('ping', {});
  console.log(result);
  // { message: 'pong', timestamp: 1748000000000 }

  await client.disconnect();
}

main();
3

Run It

Terminal 
# Terminal 1 - Start server
node server.js

# Terminal 2 - Run client
node client.js

# Output:
# { message: 'pong', timestamp: 1748000000000 }
API Reference

Server and Client API

Complete reference for building AfterLink applications.

Server Methods

new Server(config)

Create a new server instance with port, host, auth, and connection limits.

server.on(route, handler, schema?)

Register a route handler with optional Zod schema validation.

server.use(middleware)

Add Express-style middleware for auth, logging, or rate limiting.

server.publish(topic, data)

Broadcast data to all subscribers of a topic.

server.listen(port?)

Start listening for connections. Returns a Promise.

server.close()

Gracefully stop the server and disconnect all clients.

server.getConnectionCount()

Get the number of active connections.

server.getRouteCount()

Get the number of registered routes.

Client Methods

new Client(url, options?)

Create a new client with timeout, reconnect, and ping settings.

client.connect()

Connect to the server and complete the HELLO handshake.

client.request(route, body)

Send a request and receive the response. Returns a Promise.

client.subscribe(topic, handler)

Subscribe to a topic for real-time updates.

client.unsubscribe(topic)

Unsubscribe from a topic.

client.publish(topic, data)

Publish data to a topic.

client.disconnect()

Gracefully disconnect from the server.

client.isConnected()

Check if the client is currently connected.

Troubleshooting

Common errors and solutions

Quick fixes for the most common issues developers encounter.

Cause: The server is not running or the port is blocked.

Fix:

# Check if server is running
pm2 status

# Check if port is open
netstat -tlnp | grep 4000

# Check firewall rules
ufw status

# Start the server
node server.js

Cause: Client connected but server did not respond to HELLO frame.

Fix:

  • Ensure you are using the correct port.
  • Check that the server is using AfterLink v1.0.0+.
  • Verify no firewall is blocking TCP traffic on port 4000.
  • Increase connectTimeout in client options if network is slow.

Cause: The request body does not match the Zod schema defined on the route.

Fix:

// Check your route schema
server.on('createUser',
  async (req, res) => { ... },
  z.object({
    name: z.string().min(2),
    email: z.string().email(),
  })
);

// Ensure client sends matching data
await client.request('createUser', {
  name: 'Ajju',        // min 2 chars
  email: 'ajju@example.com' // valid email
});

Cause: The route name sent by the client does not match any registered route on the server.

Fix:

  • Check for typos in the route name (case-sensitive).
  • Verify the route is registered before server.listen() is called.
  • Use server.getRouteCount() to confirm routes are registered.

Cause: Each idle connection uses ~50KB. 10,000 connections = ~500MB.

Fix:

  • Set maxConnections in server config to limit concurrent connections.
  • Use server.getConnectionCount() to monitor active connections.
  • Implement idle timeout to disconnect inactive clients.
  • Scale horizontally with multiple server instances.

Cause: Another process is already listening on the port.

Fix:

# Find the process using the port
lsof -i :4000
# or
netstat -tlnp | grep 4000

# Kill the process
kill -9 <PID>

# Or use a different port
const server = new Server({ port: 4001 });

Cause: Subscription was not completed before publish, or topic name mismatch.

Fix:

  • Ensure await client.subscribe() completes before publishing.
  • Verify topic names match exactly (case-sensitive).
  • Check that the server is using server.publish() not router.publish().
